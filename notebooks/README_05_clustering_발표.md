## 1. 베이스라인 군집 (`05_clustering.ipynb`)

### 목적

- **비지도학습**으로 이용 패턴이 비슷한 고객 묶기
- **Target(이탈)은 군집 입력에 사용하지 않음** → 데이터 누수 방지
- 군집 완성 **후** 이탈률로 검증

### 사용 변수 (행동 5개)

거래건수, 한도소진율, 리볼빙잔액, 보유상품 수, 문의횟수 등 → `StandardScaler` 후 K-Means

### 모델 선정

- k = 2~8 탐색 (Elbow + Silhouette)
- **k = 3** 확정 (Silhouette ≈ **0.218**, k=2와 동률이나 해석력 우수)

### 3개 군집 (행동 기준)

| 군집 | 이름 | 특징 | 이탈률 | 전략 |
|------|------|------|--------|------|
| **0** | 동면 위험형 | 한도소진·리볼빙 ≈ 0, 카드 방치 | **가장 높음** | 재활성화 캠페인 |
| **1** | 한도 락인·다상품형 | 한도소진·리볼빙·상품 수 최고 | 낮음 | 크로스셀·한도 상향 |
| **2** | 우량 활성형 | 거래건수 압도적, 문의 적음 | **가장 낮음** | VIP·프리미엄 혜택 |

### 한계 (→ 2차 접근으로 이어지는 포인트)

- Silhouette **0.22** — 군집 경계가 느슨함 (행동이 연속 스펙트럼에 가깝다)
- “거래가 **줄어든** 고객”과 “**원래부터** 적게 쓰는 고객”을 **같은 ‘저활동’으로 묶기 어려움**

**발표 한 줄:**  
> “행동만으로도 위험군(동면형)은 보였지만, **조기 경보**에는 ‘예상 대비 얼마나 줄었는지’가 필요했다.”

## 2. 갭(Gap) 기반 군집 — 핵심 아이디어

### 정의

```
예상_대비_거래_차이 = 실제_거래건수 − 예측_거래건수
```

- **예측 거래건수**: 회귀 모델(XGBRegressor 등)이 고객 프로필로부터 추정
- **음수**: 예상보다 **덜** 씀 → 활동 **급감** 신호
- **양수**: 예상보다 **더** 씀 → **우량** 신호

### 군집 피처 (2개만 사용)

| 변수 | 의미 |
|------|------|
| `예상_대비_거래_차이` | **조기 경보** — 갑자기 줄었는지 |
| `실제_거래건수` | **절대 수준** — 원래 저활동 vs 급감 구분 |

> **중요:** `Target`(이탈)은 **굹집에 넣지 않음**. 라벨은 **사후 검증·네이밍**에만 사용.

### 파이프라인

```
회귀 모델 → 예측 거래건수
    ↓
예상 대비 차이 계산
    ↓
StandardScaler → KMeans / GMM
    ↓
Silhouette 평가 → k=3
    ↓
비즈니스 라벨 부여 → 캠페인 우선순위
```

## 3. 모델 비교 및 선정 (`05_2clustering.ipynb`)

### 후보 모델

| 모델 | Silhouette 목표 | 특징 |
|------|-----------------|------|
| **KMeans** | **≥ 0.4** | 거리 기반, 해석 단순 |
| **GMM** | **≥ 0.3** | 타원형 군집·소속 확률, 유연 |

### 탐색 범위

- k = 2 ~ 8
- GMM: `full`, `tied`, `diag`, `spherical` 공분산 구조 비교

### 최종 선정 (`05_2clustering` — Test 고객)

| 항목 | 값 |
|------|-----|
| **최종 모델** | **KMeans** |
| **군집 수** | **k = 3** |
| **Silhouette** | **0.407** |
| **데이터** | Train/Val/Test **6:2:2**, 군집은 **Test**만 |

### k=3을 고른 이유 (k=2가 Silhouette 더 높아도)

- k=2는 통계적으로는 깔끔하지만 **케어 단계가 2개**뿐
- **우선케어 · 일반관리 · 우량** 3단계가 **마케팅·CS 운영**에 맞음
- k=3도 Silhouette **0.4 이상** → 품질 기준 충족

## 4. 최종 결과 — 3개 고객군 (`05_2clustering`, Test 기준)

| 비즈니스 라벨 | 고객 수 | 평균 갭 | 평균 실제 거래 | 해지율(%) | 해석 |
|---------------|---------|---------|----------------|-----------|------|
| **우선케어(거래 감소)** | 644 | **−8.1** | 69.5 | 11.0 | 거래는 있는데 **예상보다 급감** → **조기 개입 1순위** |
| **일반관리(유지)** | 633 | −1.3 | 37.7 | 35.2 | **원래 적게 씀** → 갭≈0, 만성 저활동 |
| **우량(예상 이상)** | 749 | **+7.6** | 83.2 | 4.4 | 기대 이상 사용, **VIP·유지** |

### 라벨 부여 규칙

1. **평균 갭이 가장 작은(음수) 군집** → 우선케어(거래 감소)
2. **평균 갭이 가장 큰(양수) 군집** → 우량(예상 이상)
3. **나머지** → 일반관리(유지)

> 해지율 **순**이 아니라 **갭(활동 변화)** 순 — “아직 이탈 전이지만 줄어든” 고객을 먼저 잡기 위함.

### `05_1clustering`과의 차이 (참고)

| | `05_1clustering` | `05_2clustering` |
|--|------------------|------------------|
| 모델 | KMeans만 | KMeans + GMM |
| 라벨 | 우선케어 / **저활동·고위험** / 우량 | 우선케어 / **일반관리** / 우량 |
| Silhouette | 0.406 | 0.407 |

저활동·고위험(Cluster 0)과 일반관리(Cluster 2)는 **같은 “원래 적게 쓰는” 축** — 네이밍만 다름.

## 6. 시각화 — 발표에서 설명할 그림

### (1) 산점도: 실제 거래 vs 예상 대비 차이

- **세로축**: 실제 거래건수
- **가로축**: 예상 대비 거래 차이
- **점선(x=0)**: 예상과 실제가 같은 경계

| 색/군 | 위치 | 한 줄 설명 |
|-------|------|------------|
| **우선케어** | 점선 **왼쪽**, 거래량 중~상 | “많이 쓰던 사람인데 **기대치 미달**” |
| **일반관리** | **아래쪽**, 갭 ≈ 0 | “**원래 적게** 써서 갭이 0 근처” |
| **우량** | 점선 **오른쪽**, 거래량 상 | “**기대 이상** 사용” |

### (2) PCA 2D

- 2차원으로 압축해 **3군집이 공간에서 갈리는지** 확인
- 파랑/주황/초록 구역이 분리되면 → 군집 품질 양호

### (3) Silhouette

- 전체 + **군집별** 평균 Silhouette
- 특정 군집만 음수 → 다른 군집과 **겹침** 많음 (일반관리군에서 종종 발생)

## 7. 분류 · 회귀 · 군집 — 역할 분담

| 분석 | 질문 | 산출물 |
|------|------|--------|
| **분류** | 이 고객, **이탈할까?** | 이탈 **확률** |
| **회귀** | 프로필상 **얼마나 써야 정상?** | 예측 거래건수 → **갭** |
| **군집** | **어떤 유형**인가? | 우선케어 / 일반관리 / 우량 |

### 결합 예시 (의사결정 매트릭스)

| 이탈 확률 | 군집 | 액션 |
|-----------|------|------|
| 높음 | 우선케어 | **즉시** 리텐션 콜·혜택 |
| 높음 | 일반관리 | 재활성화 (이미 저활동) |
| 낮음 | 우선케어 | **조기 경보** — 아직 이탈 전, **1순위 케어** |
| 낮음 | 우량 | VIP 유지, 업셀 |

**발표 클로징 한 줄:**  
> “분류는 **누가 위험한지**, 회귀+군집은 **왜·어떤 유형인지**를 알려 준다.”

## 8. Q&A 예상

**Q. 이탈(Target)을 군집에 안 쓰면 정보 낭비 아닌가?**  
→ 군집은 **유형 발견**용. Target을 넣으면 “이탈/비이탈”만 나뉘어 **행동 세그먼트**가 사라짐.

**Q. Silhouette 0.4면 높은 편인가?**  
→ 2차원·행동 데이터에서는 **0.4+면 실무적으로 충분**한 편. 베이스라인 0.22 대비 **큰 개선**.

**Q. 우선케어인데 해지율이 일반관리보다 낮은 이유?**  
→ 라벨은 **“아직 이탈”**이 아니라 **“거래 급감”** 기준. 해지율은 **사후 확인**용.

**Q. KMeans vs GMM?**  
→ Test 실험(`05_2`)은 KMeans, 배치(`gap`)는 GMM. 둘 다 k=3·Silhouette 목표 충족. **발표·운영 중 하나로 통일**해도 됨.

**Q. k=2가 더 좋지 않나?**  
→ 통계 vs **비즈니스**. 3단계 케어가 운영에 유리해 **k=3** 선택.
